# Architecture

Short map of the codebase. The full rationale is in [design.md](../design.md) §3–§7.

## Layers

Each feature in `src/features/<name>/` has up to three layers:

```
presentation  →  domain  ←  data
```

| Layer | Contains | May import |
|---|---|---|
| `domain` | Entities, rules, pure functions (muraja'ah intervals, ayah numbering, audio URLs) | Nothing from the app, no React |
| `data` | API clients, zod schemas, SQLite queries, mappers, repositories | `domain` |
| `presentation` | Screens, components, query and mutation hooks | `domain`, and `data` only through hooks |

Screens never call `fetch` or SQLite directly. Repositories return `Result<T, AppError>` from
`src/lib/result.ts` and never format user-facing text.

## Folders

```
src/
  app/            expo-router routes: (onboarding), (tabs), surah/[number]
  features/       audio, hafalan, onboarding, prayer, qibla, quran, settings
  components/     shared UI primitives (Button, Screen, ModalSheet, Toast, FluidTabBar...)
  lib/            db + migrations, i18n + locales, query client, logger, result type, storage
  theme/          palette and navigation transitions
plugins/          Expo config plugins (release signing, size optimisation)
server/           FastAPI hafalan scoring service
```

## State

| Kind | Tool | Rule |
|---|---|---|
| Server data | TanStack Query | Query keys defined once per feature (`quran-keys.ts`) |
| UI state | zustand | Player, onboarding, theme, last read. Never mirrors query data |
| Preferences | MMKV | Flat, small values |
| Content and history | `expo-sqlite` | Plain SQL, migrations in `src/lib/db` |

## Data flow

```
screen → feature hook (TanStack Query) → repository → API (zod) ┐
                                                   └→ SQLite ←──┘  offline-first cache
```

Remote payloads cross a zod schema first, so shape changes are fixed in `schema.ts`, not in UI.

## Platform

- `android/` and `ios/` are committed and generated by `expo prebuild`. Change native behaviour
  through config plugins in `plugins/`, never by hand.
- Error codes: `network`, `timeout`, `parse`, `notFound`, `permission`, `server`. The UI maps
  them to i18n messages.

## Testing

Jest (`jest-expo`) with `@testing-library/react-native`. Tests run with `TZ=Asia/Jakarta`
because `adhan` derives the prayer day from local date getters. Migrations are tested against
real SQLite (`sql.js`). See [development.md](development.md).
